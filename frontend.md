# Требования к фронтенду

Для успешной сдачи проекта frontend должен соответствовать требованиям ниже. Этот раздел является обязательным ориентиром для дальнейшей разработки.

## 1. Технические Требования К Коду

TypeScript: проект должен быть написан с использованием TypeScript, все файлы должны иметь расширение `.tsx` или `.ts`.

Типизация: все функции, методы и данные с сервера должны быть строго типизированы.

Запрет на `any`: использование типов `any` и `never` запрещено. При крайней необходимости их использования требуется письменная аргументация.

Архитектура папок:

- `src/components/` - переиспользуемые компоненты;
- `src/ui/` - кастомные визуальные элементы: кнопки, инпуты, селекты;
- `src/utils/` - утилитарные функции.

## 2. Управление Состоянием

Хранилище: организовано с помощью `react-redux` и Redux Toolkit.

Слайсы: необходимо создать не менее 3 собственных слайсов.

Один из кастомных слайсов должен ссылаться на другой и использовать его actions.

Обязательные хранилища, не учитываемые в общем количестве:

- хранилище пользователя: данные о пользователе, статус авторизации и дополнительные параметры;
- хранилище настроек: данные о загрузке с сервера, управление модальными окнами ошибок.

## 3. Работа С Сетью И UI

Axios: реализация методов `GET`, `POST`, `PUT`, `DELETE`, `PATCH`.

Визуализация загрузки: каждый запрос к backend должен сопровождаться индикатором загрузки.

Обработка ошибок: при получении не 200-х кодов должна отображаться модальная форма с ошибкой.

Оптимизация: запросы при старте должны проходить строго 1 раз без дублирования.

## 4. Роутинг И Страницы

Многостраничность реализуется через `react-router-dom`.

Необходимые страницы:

- приветствие, лендинг;
- авторизация и регистрация;
- личный кабинет и страница данных после авторизации;
- 3 дополнительные уникальные страницы по тематике backend;
- страница 404 с возможностью возврата в корень дерева путей.

Оберточные компоненты:

- `AuthWrapper` - контроль авторизации;
- `CommonWrapper` - контроль общего состояния.

## 5. UI/UX И Стилизация

Стили: можно использовать библиотеки MUI, Bootstrap, Antd или чистый CSS/SCSS/SASS.

Интерфейс должен быть понятным. У каждой кнопки должна быть подпись, иконка или tooltip с пояснением.

## 6. Процесс Отчета И Проверки

Проект должен собираться без ошибок через `yarn/npm/bun build`.

Запуск через `start` не должен приводить к 500-м ошибкам страниц.

Все запрошенные страницы должны возвращать код 200.

При отсутствии доступа страницы должны возвращать коды 401, 403 или 404.

# Документация по фронтенду

Документ описывает текущее состояние приложения из папки `frontend`.

## Назначение

Фронтенд - React-приложение для платформы управления хакатонами. Основные сценарии:

- публичный просмотр хакатонов и карточки конкретного хакатона;
- регистрация и вход пользователя;
- личный профиль пользователя;
- административное создание организаторов и хакатонов;
- назначение организаторов на хакатоны;
- подача командной заявки участником;
- добавление в заявку существующих участников по логину;
- добавление новых участников с выдачей invite-ссылок.

В проекте еще остается legacy quote-код из исходного шаблона. Он не является целевым доменом и должен постепенно удаляться.

## Роутинг

Роуты описаны в `src/routes.tsx`.

Публичные:

- `/` - главная страница;
- `/hackathons` - список хакатонов;
- `/hackathons/:hackathonId` - карточка хакатона;
- `*` - страница 404.

Гостевые:

- `/register` - регистрация;
- `/login` - вход.

Приватные:

- `/admin` - административная панель.

## Обертки доступа

`AuthWrapper`

- при первом рендере вызывает восстановление авторизации;
- использует флаг инициализации, чтобы не запускать восстановление повторно.

`GuardWrapper`

- защищает приватные страницы;
- неавторизованного пользователя отправляет на `/login`;
- проверяет роли, если маршрут задает `roles`.

`GuestWrapper`

- защищает страницы входа и регистрации от уже авторизованных пользователей.

`CommonWrapper`

- отслеживает глобальный `settings.isLoading`;
- блокирует контент и показывает индикатор загрузки.

## Redux Store

Store создается в `src/store/index.ts`.

Подключены слайсы:

- `auth` - авторизация и текущий пользователь;
- `settings` - глобальная загрузка и модальная ошибка;
- `hackathons` - список, активный и текущий хакатон, поля формы;
- `teams` - команды хакатона и последние invite-ссылки;
- `admin` - список организаторов;
- `quotes` - legacy слайс из шаблона.

Typed hooks:

- `useAppDispatch`;
- `useAppSelector`.

## API

Основной axios-инстанс находится в `src/api/axios.ts`.

Настройки:

- `baseURL` из `VITE_API_URL` или `/api/v1`;
- `timeout: 10000`;
- `Content-Type: application/json`;
- `accessToken` из `sessionStorage` добавляется как `Authorization: Bearer ...`.

Response interceptor:

- ловит `401`;
- если запрос еще не повторялся и это не `/auth/refresh`, пытается обновить токены;
- при успехе сохраняет новую пару токенов и повторяет исходный запрос;
- при ошибке очищает токены и пробрасывает ошибку.

API-адаптеры находятся в `src/api/hackathonApi.ts`:

- `authApi`: login/register/refresh/me;
- `adminApi`: список организаторов, создание организатора, назначение организатора;
- `hackathonApi`: список, активный хакатон, получение, создание, обновление, поля формы;
- `teamApi`: список команд, создание заявки, изменение статуса команды, дисквалификация участника.

## Mock Backend

`mock-backend/server.mjs` реализует основные endpoints текущего фронтенда:

- auth;
- users/me;
- admin organizers;
- hackathons;
- form fields;
- registrations;
- teams;
- team status;
- member actions;
- feedback/export;
- часть legacy quote endpoints.

Для командной заявки mock backend:

- принимает `POST /hackathons/:hackathonId/teams`;
- создает команду;
- связывает существующих участников по `login`;
- создает invite-записи для новых участников;
- возвращает `invitationLinks`.

Для модерации mock backend:

- фильтрует `GET /hackathons/:hackathonId/teams?status=...`;
- принимает `PATCH /hackathons/:hackathonId/teams/:teamId/status`;
- сохраняет `moderationReason`;
- принимает `POST /hackathons/:hackathonId/teams/:teamId/members/:memberId/disqualify`.

Для регламента mock backend:

- принимает `PUT /hackathons/:hackathonId/rules`;
- создает PDF file asset;
- сохраняет файл в `hackathon.rulesFile`;
- возвращает обновленный `Hackathon`.
